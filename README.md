# Debian 13 Server Setup — Полная настройка сервера

![Debian](https://shields.io)
![Bash](https://shields.io)

Набор адаптивных интерактивных скриптов для автоматизации развертывания, обеспечения безопасности, очистки, диагностики и резервного копирования серверов под управлением **Debian 13 (Trixie)** и **Debian 12 (Bookworm)**.

---

## 🔥 Что включено

### Базовая настройка и репозитории
* **Обновление системы:** Безопасный апгрейд пакетов с флагами подавления интерактивных окон.
* **Расширенные репозитории:** Автоматическое подключение компонентов `contrib`, `non-free` и `non-free-firmware`.
* **Авто-апдейты:** Конфигурация службы `unattended-upgrades` для фоновой установки обновлений безопасности.
* **Системное окружение:** Автоматическая генерация локали `ru_RU.UTF-8`, установка часового пояса `Asia/Yekaterinburg`, создание файла подкачки (SWAP) на 1GB и лимитирование ротации системного журнала `journald` (до 800MB/2 недели).

### Сеть и DNS/NTP службы
* **Сетевой стек:** Миграция и адаптивная настройка сети через современный `systemd-networkd`.
* **Быстрый DNS:** Конфигурация отказоустойчивого кэширующего DNS-слоя через `systemd-resolved` (Google + Cloudflare).
* **Синхронизация времени:** Развертывание `systemd-timesyncd` с использованием пулов времени от Yandex и NTP Pool.

### SSH и Комплексная Безопасность
* **Защита доступа:** Смена стандартного порта SSH, блокировка входа для пользователя `root`, отключение аутентификации по текстовым паролям и ограничение доступа по директиве `AllowUsers`.
* **Менеджмент ключей:** Интерактивный импорт существующих публичных ключей со стороны Windows/Linux клиентов или генерация новой пары ключей `ed25519` прямо на хосте.
* **Брандмауэр и Защита:** Развертывание и блокировка несанкционированного трафика через `UFW`, а также автоматическая защита от брутфорса через связку `fail2ban` + `nftables`.

### Развертывание Docker и Сервисов
* **Контейнеризация:** Установка актуальной версии `Docker Engine` и плагина `Docker Compose`.
* **Проксирование:** Интерактивное развертывание контейнера `Nginx Proxy Manager` для управления SSL-сертификатами и доменами.
* **Связность и Бэкапы:** Установка защищенного VPN-клиента `NetBird` и консольного инструмента синхронизации с облаками `RClone`.

### Диагностика, Очистка и Бэкапы
* **Обслуживание:** Автоматическая глубокая очистка кэша APT, старых логов, остаточных файлов контейнеров Docker, а также добавление еженедельной задачи очистки в системный `cron`.
* **Мониторинг:** Модуль экспресс-аудита системы с возможностью опциональной установки `NetData` (веб-панель реального времени) и `Node Exporter` (метрики для Prometheus).
* **Резервное копирование:** Скрипт интеллектуального локального сжатия важных директорий (`/opt`, `/var/lib/docker`, `/etc`, баз данных и т.д.) с последующей автоматической выгрузкой архивов в облако RClone. Структура удаленных каталогов автоматически именуется на основе текущего `Hostname` сервера.

## 📋 Структура скриптов

| № | Файл | Описание |
|---|---|---|
| 1 | `01-system-audit.sh` | Первичный аудит архитектуры, сети, действующих портов и создание слепка конфигураций. |
| 2 | `02-initial-setup.sh` | Обновление пакетов, развертывание базовых утилит (`htop`, `mc`, `curl`), настройка репозиториев и Hostname. |
| 3 | `03-network-dns-ntp.sh`| Перевод сети под управление `systemd`, настройка быстрых DNS-серверов и синхронизация времени. |
| 4 | `04-ssh-security.sh` | Создание sudo-пользователя, импорт ключей, перенос порта SSH, конфигурирование UFW, SWAP и Fail2Ban. |
| 5 | `05-install-services.sh`| Интерактивный менеджер установки Docker, Docker Compose, NetBird, Nginx Proxy Manager и RClone. |
| 6 | `06-system-cleanup.sh` | Глубокий клининг дискового пространства и внедрение скрипта авто-очистки в планировщик. |
| 7 | `07-system-diagnostic.sh`| Сбор детального диагностического отчета, выявление ошибок в логах и опциональный накат NetData/Node Exporter. |
| 8 | `08-backup-setup.sh` | Настройка локального бэкапа данных, привязка удаленного облака RClone и автоматизация задач в crontab. |

## 🚀 Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd debian13-server-setup
```

### 2. Выдача прав на выполнение
```bash
chmod +x *.sh
```

### 3. Последовательный пошаговый запуск
> **Важно:** Все скрипты запускаются строго с привилегиями суперпользователя (`root`).

```bash
sudo ./01-system-audit.sh        # Шаг 1: Аудит и создание резервных копий
sudo ./02-initial-setup.sh       # Шаг 2: Базовые пакеты и репозитории
sudo ./03-network-dns-ntp.sh     # Шаг 3: Конфигурация сети, DNS и NTP
sudo ./04-ssh-security.sh        # Шаг 4: Безопасность, SSH, UFW, SWAP
sudo ./05-install-services.sh    # Шаг 5: Развертывание Docker и сопутствующих сервисов
sudo ./06-system-cleanup.sh      # Шаг 6: Первичная очистка мусора и создание cron-задачи
sudo ./07-system-diagnostic.sh   # Шаг 7: Диагностический тест и сборка отчета
sudo ./08-backup-setup.sh        # Шаг 8: Автоматизация резервного копирования (Локал + Облако)
```

## 📁 Архитектура каталогов резервного копирования

### Локальные бэкапы аудита (Шаг 1)
Создаются автоматически перед внесением изменений и хранятся в корневом разделе:
```text
/root/backup_YYYYMMDD_HHMMSS/
├── system_config.conf       # Файл параметров, используемый последующими скриптами
├── audit.log                # Лог выполнения первичного аудита
├── interfaces.backup        # Копия старых сетевых настроек
├── resolv.conf.backup       # Копия старого конфигуратора DNS
├── hosts.backup             # Старая таблица локального разрешения имен
└── ssh/                     # Копия исходных конфигурационных файлов SSH демона
```

### Структура регулярного бэкапа данных (Шаг 8)
Локальные ежедневные архивы сохраняются в `/backup/data` и ротируются раз в 7 дней. При наличии подключенного облака `RClone` скрипт дублирует их в удаленное хранилище по следующей иерархии:
```text
[Ваше_Облако]:server_backups/
└── [Имя_Текущего_Hostname_Сервера]/
    ├── data_20260301_020000.tar.gz
    ├── data_20260302_020000.tar.gz
    └── upload_20260302.log
```

## ⚠️ Важные замечания для администратора

1. **Снапшоты:** Перед стартом выполнения скриптов (в особенности Шага 3 и Шага 4) настоятельно рекомендуется сделать полный снимок (Snapshot) вашей виртуальной машины на стороне провайдера VPS.
2. **Контроль сессии SSH:** После выполнения Шага 4 **не закрывайте текущую сессию терминала**. Откройте новое окно и попробуйте подключиться к серверу по сгенерированному ключу и новому порту. Пример команды входа:
   ```bash
   ssh -p 22444 имя_пользователя@IP_АДРЕС_СЕРВЕРА
   ```
3. **Порт 22:** Если на шаге 4 вы решили не закрывать порт 22 сразу, вы всегда можете сделать это позже вручную с помощью команды `sudo ufw delete allow 22/tcp && sudo ufw reload`.

## 🛠️ Устранение экстренных проблем

### Быстрое восстановление доступа к SSH через VNC-консоль
Если вы потеряли доступ к серверу из-за блокировки брандмауэра, откройте встроенную веб-консоль (VNC) вашего хостинг-провайдера и выполните:
```bash
ufw allow 22/tcp
ufw allow 22444/tcp   # (Укажите ваш кастомный порт вместо 22444)
systemctl restart ssh ufw
```

### Проверка работоспособности ключевых защитных служб
```bash
systemctl status ssh ufw fail2ban docker netbird
ufw status verbose
fail2ban-client status sshd
```
